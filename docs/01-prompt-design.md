# Prompt 设计逻辑
## 1. 意图识别设计
### 1.1 分类标准
统一四类用户意图，覆盖客服全业务场景：
- `simple`：简单通用问答
- `before_sale`：售前咨询（尺码、优惠、商品咨询）
- `after_sale`：售后问题（退货、物流、投诉、订单查询）
- `transfer_human`：强制转人工场景

### 1.2 输出格式化约束
通过严格Prompt约束+Few-shot示例，强制大模型**仅输出标准JSON格式**，无多余自然语言冗余内容，保证下游程序可稳定解析：
```json
{"intent": "after_sale", "complexity": "high", "reason": "用户申请退货，需要核对订单信息"}
```

## 2. Agent 角色边界规范
为不同业务Agent设定严格权限边界，杜绝越权应答、幻觉问题：
### 2.1 售前Agent
仅负责商品尺码推荐、平台优惠活动查询，**禁止处理退款、售后投诉、物流异常等售后业务**。

### 2.2 售后Agent
专注处理订单查询、退货申请、物流查询、用户投诉等售后场景；
核心约束：**无有效订单号时，严禁捏造订单数据，必须主动向用户索要订单信息**。

### 2.3 RAG 知识库联动机制
所有Agent前置**知识检索节点**，自动匹配平台售后政策、商品规则等知识库内容；
通过代码节点将检索结构化数据转为纯文本注入Prompt，极大抑制大模型幻觉，保障应答合规准确。

## 3. 转人工暗号核心机制
针对Dify1.16版本内联Agent多步调用不稳定问题，自研字符串触发式人工转接方案：
1. 核心原理：Prompt强制约束，模型无法处理、用户情绪过激、业务超出权限时，回复末尾固定输出暗号：`[SYSTEM_ACTION: HANDOFF_REQUESTED]`
2. 技术优势：相较于传统意图枚举匹配，大模型固定字符串输出准确率更高、稳定性更强
3. 业务闭环：n8n网关实时嗅探该暗号，自动触发飞书人工通知，完成用户转接

## 4. 会话变量提取与跨轮记忆
### 4.1 输出格式约束
要求LLM应答末尾固定标签化输出用户信息：`[情绪: 愤怒] [订单号: SO20250101] [需求: 退货退款]`

### 4.2 变量映射逻辑
通过Dify代码节点正则解析标签内容，赋值至全局会话变量：`user_emotion`、`user_size_preference`、`user_order_id`等，实现多轮对话用户画像、业务信息持久化记忆。
